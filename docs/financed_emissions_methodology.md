# Financed Emissions Methodology

> **All figures are computed from synthetic activity data and synthetic /
> illustrative emission factors on a synthetic demonstration portfolio.**
> This is not an emissions inventory of any real institution.

Wave 3 PHASE-05 adds a PCAF-style (Partnership for Carbon Accounting
Financials) financed-emissions layer, implemented in `R/financed_emissions.R`
and run by `scripts/generate_financed_emissions.R`. It is purely additive: it
reads the already-published `engagement_priority.csv` for matched exposure,
never feeds `composite_score`, the sector ranking, or any other frozen
artifact, and can be reproduced by hand with a calculator from the formulas
below — the same standard `docs/scoring_anchors.md` sets for the severity
scores.

## Scope

**Scope 1+2 only.** Automotive and coal-mining borrowers are excluded —
their financed emissions are overwhelmingly Scope 3 (tailpipe emissions for
automotive; downstream combustion for coal), and a Scope 1+2-only figure for
those sectors would understate exactly the borrowers that matter most. Every
row for an excluded borrower carries `exclusion_reason =
"scope_3_dominant_sector_out_of_scope"` rather than a silent `NA`. The
`scope` column is populated with the literal `"1+2"` on every computed row
from day one, so a future Scope 3 extension is a new set of rows, not a
schema migration.

## Formulas

For borrower *b*:

```
attribution_factor_b = clamp(outstanding_vnd_b / borrower_capital_vnd_b, 0, 1)
financed_emissions_tco2e_b = attribution_factor_b * borrower_emissions_tco2e_b
```

- `outstanding_vnd_b` — this bank's total exposure to borrower *b*, whole
  VND, from `output/engagement/engagement_priority.csv`'s `exposure_vnd`.
- `borrower_capital_vnd_b` — borrower total debt + equity, whole VND, from
  `data/vietnam_borrower_capital.csv` (see "Capital sourcing" below).
- `clamp(x, 0, 1)` — a ratio above 1 (the loan exceeds the borrower's total
  capital) indicates a data error and is capped at 1, not extrapolated.

**Power** (capacity-based, since ABCD reports installed capacity, MW, not
generation):

```
borrower_emissions_tco2e_b = capacity_MW * capacity_factor * 8760 * emission_factor_tCO2_per_MWh
```

summed across every technology (coal/gas/hydro/renewables) the borrower
operates. `capacity_factor` and `emission_factor_tCO2_per_MWh` come from
`data/vietnam_capacity_factors.csv` and `data/vietnam_emission_factors.csv`
respectively (technology-level, synthetic/illustrative — see those files'
`source` columns). `8760` is hours in a non-leap year, used for every year
without adjustment.

**Cement / steel** (intensity-based):

```
borrower_emissions_tco2e_b = production_tonnes * emission_factor_tCO2_per_tonne
```

Both `production` and `emission_factor` come directly from
`data/vietnam_abcd.csv`'s own columns for that borrower — no lookup table
needed, since ABCD already reports borrower-specific emission factors for
these two sectors (`data_source: synthetic_demo`, but structurally
"reported" quality — see below).

## Capital sourcing (ASM-005)

There is no real balance-sheet data for the synthetic borrowers in this
demo, so `data/vietnam_borrower_capital.csv` derives an illustrative
`borrower_capital_vnd` per company:

- **When a `debt_equity_ratio` exists** (`data/vietnam_trisk_financial_features.csv`,
  17 of 25 companies): `capital = outstanding_vnd * (1 + 1/debt_equity_ratio)`
  — treating this bank's own exposure as an approximation of the borrower's
  total debt, so `debt * (1 + equity/debt) = debt * (1 + 1/DE)`. Quality:
  `capital_source = "reported"`.
- **Otherwise**: `capital = outstanding_vnd * 3.0` (an illustrative
  leverage multiplier) when exposure is known, or a fixed 2 trillion VND
  fallback when neither exposure nor a D/E ratio is available. Quality:
  `capital_source = "sector_median"`.

This file is a standalone sidecar (`data/vietnam_borrower_capital.csv`),
deliberately **not** added to `data/vietnam_trisk_financial_features.csv`
even though that would be the more natural home — that file is generated by
`R/trisk_core.R`'s `.trisk_company_archetypes` and consumed directly by
`trisk.model::run_trisk()`; adding columns to it was tested and found to
change the row *content* `write_csv()` produces on regeneration, which would
have broken TRISK's byte-identity guarantee (CLAUDE.md Law 5). The sidecar
carries zero TRISK risk.

## Data-quality scoring (1 = best, 5 = worst)

Note this direction is the **opposite** of every severity score elsewhere
in this repo, where 1 is worst — labelled explicitly wherever it appears.
Evaluated top to bottom, first match wins:

1. **Any input a sector-median assumption** (including a sector-median
   `borrower_capital_vnd`) → **5**.
2. **Activity data is derived, not reported** (power: capacity + capacity
   factor, not metered generation) → **4**.
3. **A technology-level (not borrower-specific) emission factor** → **3**.
4. **Everything reported and borrower-specific** → **2**.

Score **1** (audited, third-party-verified emissions) is never assigned by
this synthetic pipeline — there is nothing to audit.

**No total is ever published without its quality-weighted composition.**
`data_quality_summary()` computes, per score, the share of total financed
emissions at that quality level; every generated report shows this table
alongside any total.

## Carbon-cost exposure

```
carbon_cost_vnd = financed_emissions_tco2e * carbon_price_usd_per_tco2 * fx_rate_usd_vnd
```

using the `increasing_carbon_tax_50` central scenario from
`data/vietnam_trisk_ngfs_carbon_price_<sector>.csv` (the same central case
TRISK's own base-parameter scenario uses). When `inputs.fx_rate_usd_vnd` is
not configured for an engagement, every `carbon_cost_vnd` is `NA` and the
generated report says so explicitly rather than showing a silently-wrong
number.

## Two benchmarks, one number each — a note on duality

This platform now computes two structurally different quantities that both
get called "the PDP8 target": PACTA alignment gaps are measured against the
scenario *benchmark* (how far the portfolio is from a pathway), while
sector interim targets (a later Wave 3 workstream) are computed by
*convergence* from the portfolio's own baseline. Financed emissions is a
third, independent construct — an inventory, not a gap or a target — and
should not be confused with either. State which one you are quoting.
