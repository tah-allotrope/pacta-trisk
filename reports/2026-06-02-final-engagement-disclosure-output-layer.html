Executive Summary

02 / Background & Objective

Background & Objective

The pacta-trisk repository is a synthetic demonstration of climate analytics for a fictional "Mekong Commercial Bank (MCB)" in Vietnam. Two methods sit at its core: PACTA measures whether a bank's financed production (power capacity, vehicle mix, cement/steel intensity) is aligned with Paris-consistent pathways such as Vietnam's Power Development Plan VIII (PDP8); TRISK stress-tests each borrower by re-pricing its assets and probability of default under a late-and-sudden policy shock.

Those analytics already existed in the repo as committed result files and a public Streamlit dashboard. What was missing — flagged as "Idea 3" in the commercial-demo triage — was the last mile: the layer that takes the analytics and produces something a banker hands to a borrower or files with the regulator. The objective of this multi-phase effort was to build exactly that, with a strict rule that it only synthesises existing outputs and runs no new model.

03 / Inputs & Scope

Inputs & Scope

Inputs used (all pre-existing)

  • TRISK borrower results for power, cement, steel (top_borrowers_alignment_trisk.csv) — already carry the alignment gap, NPV/PD change, and a 0–100 stress-priority score.
  • PACTA company alignment (04_vn_ms_company.csv) for automotive — no TRISK pilot for that sector.
  • The matched, prioritised loanbook for VND exposure per borrower.
  • Alignment-overview and coal stranded-risk charts; PACTA, TRISK, and Decision 263 documentation for the appendix.

Scope boundary

In Composite scoring; letter + disclosure generators with editable templates; an operator-gated dashboard page; documentation; verification.

Out New PACTA/TRISK model runs; real bank-data ingestion; full Vietnamese translation of methodology prose; native DOCX/PDF rendering; exposing the operator page on the public deployment.

04 / Assumptions & Constraints

Assumptions & Constraints

Key decisions (from the six "Grill Me" questions)

  • Format: self-contained HTML + browser print-to-PDF only (no new dependencies).
  • Language: English-primary with Vietnamese key terms inline (not full side-by-side bilingual).
  • Disclosure framing: TCFD pillars + ISSB IFRS S2 + Decision 263 note.
  • Weighting: fixed 50/50 alignment vs TRISK — no operator slider.
  • Anonymisation: off by default (named board pack); operator toggle to anonymise.
  • Recipients: top-N borrowers, N=10, adjustable.

Constraints & caveats

  • Everything runs on synthetic data; every artifact carries a synthetic-data watermark and a "requires human and legal review" disclaimer.
  • Generated letters and packs are never committed to git (privacy posture); only the aggregate scoring table is tracked.
  • Cross-sector gap magnitudes are not strictly comparable (market-share percentage-points vs SDA emission-intensity percent) — the composite is a demo prioritisation aid, not a calibrated risk number.
  • Automotive borrowers lack a TRISK score and are scored on alignment only, flagged as partial rather than dropped.
05 / Methodology

Methodology

The work followed the five planned phases, each ending with verification, a phase report, and a pushed commit. The design discipline throughout was "compute once, render everywhere": a single scoring table is the only source of borrower numbers, and both generators render figures from it rather than hardcoding anything.

The composite engagement score normalises each borrower's alignment gap and TRISK stress-priority to a 0–1 range and blends them 50/50, re-normalising to whichever components are available so a borrower in a sector without a TRISK pilot is neither dropped nor unfairly buried. Letters use safe token substitution with a guard that aborts the run if any placeholder is left unfilled; the disclosure pack converts an editable markdown narrative to HTML and can anonymise every borrower name in a single verified pass. The dashboard page reuses the repository's proven operator-gating pattern so the generators never reach the public site.

06 / Phase-by-Phase Analysis

Phase-by-Phase Analysis

P1 · Scoring backbone

Built engagement_scoring.R → a 23-borrower priority table (13 power, 6 automotive-partial, 2 cement, 2 steel), sorted by composite score. The coal-heavy power names lead. Every borrower matched a loanbook exposure row.

P2 · Engagement letters

An editable HTML template + per-sector prompt CSV drive 10 one-page letters. A residual-token guard caught a stray placeholder on the first run (working as designed) and the figures were spot-checked against the data row.

P3 · Disclosure pack

One self-contained HTML pack (84 KB): exec summary, alignment vs PDP8/NDC/NZE with embedded charts, top-counterparty table, TCFD pillars with ISSB + Decision 263 notes, and a methodology appendix. An --anonymize mode removes every real name.

P4 · Operator page

A dashboard page gated behind an environment flag and a confirmation checkbox runs both generators as subprocesses, surfaces errors, and offers downloads + an inline preview. Ten new tests; full suite green.

P5 · Verification & packaging

Locked generated artifacts out of git, proved the whole chain runs clean from an empty output directory, and wrote operator + bank documentation so a newcomer can run the layer without this conversation.

The through-line

Each phase fed the next from one table: scoring → letters and disclosure → operator surface → packaging. No phase re-derived numbers; they all read the same priority CSV, which is why the artifacts are internally consistent.

07 / Findings & Recommendation

Findings & Recommendation

The layer works end to end and is internally consistent. The composite ranking puts coal-heavy power borrowers at the top — Nghi Son Power, Vinacomin Power, and International Power Mong Duong all score at or near 1.0 — which is the intuitively correct transition-risk priority for a Vietnamese power book. Automotive names (Ford, Hyundai, THACO) rank next on alignment alone, flagged as partial because the TRISK pilot does not yet cover that sector. The chart below shows the top-10 by composite score; cyan bars are TRISK-covered borrowers, gold bars are alignment-only (partial).

Recommendation: use this as the standing template for productionising the demo. The editable template + prompt CSV mean the bank can re-voice every deliverable without touching code; the operator gate and synthetic watermarks keep it safe to demo publicly while real generation stays private. The clear next investments are TRISK coverage for automotive (to remove the partial flag) and a domain/legal review of the disclosure wording before any real filing.

08 / Implementation Path

Implementation Path

Run it (command line)

From the repo root, in order:

  1. Rscript scripts/engagement_scoring.R
  2. Rscript scripts/generate_engagement_letters.R --top_n 10
  3. Rscript scripts/generate_disclosure_pack.R (add --anonymize to share externally)

Open any output in a browser; print-to-PDF for a hand-off copy.

Run it (dashboard, operator-only)

Set OUTPUTS_LAYER=1 (and R_RSCRIPT if needed), start the dashboard, open Engagement & Disclosure Outputs, tick the confirmation box, choose top-N / anonymise, and generate. Without the flag the page stays hidden.

Re-brand without code

Edit templates/engagement/letter_template.html (layout), engagement_prompt_templates.csv (per-sector wording), or templates/disclosure/disclosure_sections.md (TCFD narrative). Re-run the relevant script — figures are always re-pulled from data.

Suggested next steps

  • Extend the TRISK pilot to automotive to remove the partial-coverage flag.
  • Domain + legal review of the disclosure wording before any external use.
  • Optional: native DOCX/PDF rendering; fuller Vietnamese translation.
09 / Risks / Open Questions

Risks / Open Questions

Risks & mitigations

  • Wrong figures in a client letter → every number renders from the data row; an automated guard aborts on any unfilled placeholder.
  • Operator surface leaking to the public site → env-flag gate (reused from the proven intake page) + confirmation checkbox.
  • A real name leaking from an "anonymised" pack → single name-list replacement across the whole document, verified by search (zero real names remain).
  • Accidental commit of a generated artifact → ignore rules added before any generation run.

Open questions

  • Should exposure size become a third factor in the composite (currently alignment + TRISK only)?
  • When should automotive get a TRISK pilot so it is no longer partial?
  • Is browser print-to-PDF sufficient long-term, or is native DOCX worth the added dependency?
  • How much of the disclosure prose should be fully translated to Vietnamese for a real filing?
