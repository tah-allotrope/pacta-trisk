02 / Background & Objective

Background & Objective

The PACTA + TRISK Vietnam project evaluates climate transition risk for Vietnamese banks using fully synthetic data. Before Wave 0, the platform only served one fictional bank (Mekong Commercial Bank, MCB) in a hand-configured pipeline with manually verified outputs. The core R modules were already config-driven (commits d299496, 408e95c), but four gaps prevented a second engagement from running:

  1. No acceptance bar: Every refactor was verified by hand-rolling a full refresh plus git diff — error-prone and irreproducible.
  2. No engagement orchestrator: Running a new bank required executing 10+ scripts manually with ad-hoc paths.
  3. No multi-bank proof: Only MCB had ever run end-to-end; regressions that "work only for MCB" were undetectable.
  4. Volatile outputs: TRISK CSVs had per-invocation UUIDs in run_id/run_path, breaking byte-identity comparisons between identical runs.

Wave 0's objective was to close all four gaps in a single tightly-scoped execution cycle, produce a golden refreeze covering every fix, and guard the result with automated verification.

04 / Assumptions & Constraints

Assumptions & Constraints

Technical Constraints

  • Byte-identity acceptance applies to CSV outputs via autocrlf-aware git diff — PNGs and timestamp-bearing HTML/manifest files are classified as noise, never fail.
  • VND loanbook money is never rescaled (magnitudes 1e5–5e12 raw).
  • No --config flag → MCB defaults remain byte-identical to the pre-Wave-0 baseline.
  • R files must work both source()d and package-loaded; yaml is deliberately not a dependency — configs are JSON via jsonlite.
  • PowerShell 5.1 has no &&; all commands are portable Rscript -e "..." one-liners.
  • Streamlit Community Cloud has no R runtime; the dashboard has no R dependency.

Process Constraints

  • Weekly CI auto-commits to main (Mondays 02:00 UTC, test-gated) — a red testthat suite blocks publish by design.
  • Engagement scoring reads from the engagement snapshot, not synthesis_output/ — the orchestrator step order enforces this.
  • Vietnamese diacritics: CSVs are UTF-8 without BOM; the intake reader falls back to latin1, which silently mangles diacritics.
  • dashboard/tests/test_auth.py::test_no_password_renders_landing is a known environmental flake (hardcoded 3-second Streamlit AppTest timeout).
  • Golden literals in test files come from committed CSVs, never from plan text.
05 / Methodology

Methodology

The work was sequenced as four phases, each with shell-verifiable exit criteria gating the next, plus two parallel no-code tasks (ABCD sourcing brief and intake contract) that ran from day one:

  1. PHASE-01 — Verify tool: Build tools/verify_refactor.R first because every later phase needs it for acceptance. Proved on the untouched tree before any code moved.
  2. PHASE-02 — Orchestrator: Extract the step-runner from pipeline_refresh.R into R/step_runner.R (preserving byte-identical default-mode output), then build the engagement orchestrator with an independent manifest. Validated with --dry-run and the snapshot-dir guard rail.
  3. PHASE-03 — SDB rehearsal: Run the dirty SDB fixture through the full orchestrator. Every crash was patched with an inline guard (zero-match PACTA sectors, empty TRISK sectors, empty letter target lists). Cross-contamination verified by git status. Golden literals frozen from committed files. CI job added to refresh.yml.
  4. PHASE-04 — Data closers + refreeze: Close ABCD docs, version scenarios, fix Dung Quat and power-2025 bugs, make run IDs deterministic. Run a full pipeline, verify drift classification, freeze golden literals across both test suites, empty the volatile basenames list, commit everything as one refreeze commit. Prove determinism with two consecutive runs.

The tools/verify_refactor.R decision logic classifies each changed tracked path by the first matching rule: .png → png-noise (ignore), .html or manifest basenames → timestamp-class (list), basename in a volatile vector → volatile (list), anything else → DRIFT (fail). After the refreeze, the volatile vector is character(0) so every non-PNG/non-timestamp change fails — the strictest possible bar.

Deliverable: tools/verify_refactor.R

Codified the hand-rolled acceptance check used by the two prior refactors. The pure function classify_path() maps any tracked path to one of four classes by a priority-ordered rule cascade: extension .png → png-noise (ignored), extension .html or basenames in a manifest/timestamp set → timestamp-class (listed but not failing), basenames in a configurable volatile vector → volatile (listed but not failing), anything else → DRIFT (exits 1).

07 / Findings & Recommendation

Findings & Recommendation

Key Findings

  1. The verify tool is viable as a permanent acceptance gate. It caught real drift (scenario path changes, run-id rewrites) during Phase 4 while correctly classifying PNG noise and manifest timestamps as non-failing. After the refreeze, empty VOLATILE_BASENAMES means any non-PNG/non-timestamp change fails — the strictest possible bar.
  2. Multi-bank parameterization surfaces new edge cases. SDB's 24-row book exercised zero-matched PACTA sectors, empty TRISK sector inputs, and empty letter targets — conditions MCB's 2,200-row book never triggers. All were fixable with small inline guards behind emptiness checks that MCB's path never enters.
  3. Deterministic run IDs are essential for reproducibility. The UUID-per-invocation scheme from trisk.model::run_trisk() made every second run produce different CSVs even with identical inputs. The rewrite to sector_run_label at write time in write_trisk_demo_outputs() eliminated this volatility without modifying trisk.model itself.
  4. Weekly CI is the right cadence for SDB regression detection. The SDB engagement runs in minutes with run_grid: false (no 243-cell grid), and a weekly cadence catches regressions without taxing every PR push.

Recommendation

Push the refreeze commit to main. The commit covers scenario versioning, two bug fixes, deterministic run IDs, and both golden test suites. After push, the platform is production-safe for any new synthetic engagement: run Rscript scripts/new_engagement.R --slug <slug> --name "..."; Rscript scripts/run_engagement.R --config engagements/<slug>/engagement_config.json --raw-loanbook <csv> from a clean checkout and verify with tools/verify_refactor.R.

09 / Risks / Open Questions

Risks / Open Questions

Risks

  • CI auto-commit drift: The weekly refresh workflow auto-commits to main. If a future commit changes MCB default outputs beyond the sanctioned refreeze, the bot commit produces a dirty tree. Mitigation: the verify tool is the gate — a pre-commit hook using tools/verify_refactor.R --skip-refresh would catch it before the bot runs.
  • Hidden UUID consumer: If any dashboard or downstream code parses the run_id UUID format (now deterministic strings), it breaks silently. Mitigation: the grep sweep in Phase 4 found no such consumers; the R and Python test suites pass against refrozen data.
  • Dual scenario drift: The scenario files are dual-written by generate_vietnam_data.R. If someone edits only one copy, the md5sum assertion in test_snapshot_contract.R fails — but only when the test runs. Mitigation: run the full test suite before any commit that touches scenario files.

Open Questions

  • ABCD pricing: Asset Impact license costs are marked "to be confirmed with vendor" in the sourcing brief. The commercial trigger point ("decide before signing the data-phase start date") is documented but untested.
  • Real data ramp: The orchestrator assumes a CSV file matching the intake schema. A real bank's data will have format surprises that the synthetic fixture did not exercise. The intake validation report provides the first line of defense.
  • Engagement letter customization: The letters generator produces templated output. A real engagement may demand bank-specific branding, multiple signatories, or bilingual Vietnamese/English output that the current generator does not support.
