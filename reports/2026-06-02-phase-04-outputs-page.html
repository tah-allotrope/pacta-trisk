03 / Math / Algorithm Used

Math / Algorithm Used

No new math — this phase is a trust-boundary and process-control layer:

  • Two-factor gate: the page renders generation controls only when OUTPUTS_LAYER == "1" and the operator ticks an explicit "illustrative, synthetic, requires human review" checkbox. Either condition false ⇒ no generation possible.
  • Subprocess contract: generators run with cwd = repo root (they resolve inputs via getwd()), a 180 s timeout, and Rscript resolved from R_RSCRIPT or the default. A non-zero exit raises with the captured stderr (RISK-04-01), surfaced via st.error.
  • Fixed weighting (Q-004): the composite weight slider was intentionally dropped; weighting stays a documented 50/50 script parameter only.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Streamlit deprecation noise: the page uses use_container_width=True to match the rest of the dashboard; Streamlit now prefers width=. Functional (tests pass) but a repo-wide migration is a separate cleanup, not in this phase's scope.
  • Synchronous generation: generators run inline with a spinner (180 s timeout). For a much larger borrower set, a background-job pattern would be better; out of scope for the demo volume.
  • Second-best alternative (rejected, ALT-002): embedding generation in the existing public TRISK page. Rejected — this surface writes artifacts and is operator-gated, a different trust boundary than the read-only public views.
07 / Errors / Warnings / Flags

Errors / Warnings / Flags Encountered

  • Transient test flake: the unrelated test_trisk_page_renders (page 2) timed out once during a heavily-loaded full run that also spawns R subprocesses; it passes in isolation, as a group, and on a clean re-run (48 passed). Not caused by this phase — page 7 does not touch page 2 or its data.
  • Deprecation warnings for use_container_width (cosmetic; see Limitations).
  • No functional errors; end-to-end subprocess generation succeeded for both generators.
