BIDV MoU: expected outcomes against the repo

The English section of the MoU lists eight expected outcomes. Mapped against what pacta-trisk produces today:

A practical framework recommendation report for investment decision-making and climate risk management

Already built

This exists as a finished deliverable. reports/BIDV_Framework_Recommendation_Report.html — 133 KB, ten sections, regenerable via scripts/generate_bidv_report.R. Carries the framework landscape matrix, a three-tier recommended stack, sector prioritization, Decision 263 mapping, a five-phase roadmap, and a risk register. It needs a refresh pass against the final MoU wording, not a rebuild.

Client readiness screening framework + shortlist of three priority SLL clients

Close

The scoring machinery is built; the framing is wrong. scripts/engagement_scoring.R ranks borrowers into engagement_priority.csv on an absolute severity composite and generate_engagement_letters.R renders per-borrower letters with a --top_n flag. It screens on transition risk and misalignment, which is not the same axis as SLL readiness (data availability, KPI feasibility, client appetite). Reframing it is a scoring-input change plus a template change, not new infrastructure.

Baseline report identifying portfolio hotspots and priority sectors for client engagement

Close

Hotspot identification works, from a different input. docs/bidv_sector_prioritization_methodology.md and the sector prioritization report rank sectors, but from PACTA alignment gaps and TRISK stress — not from a PCAF financed-emissions inventory, which is what the MoU means by "baseline". The output shape is right; the input layer is the gap below.

Virtual workshop for smaller Vietnamese banks, using anonymized GTB tools

Close

The anonymization requirement is already met. generate_disclosure_pack.R --anonymize was verified to produce zero real names, and intake/ ships schema docs plus CSV templates that are exactly the "common data quality issues / data collection protocols" material the MoU describes. The public dashboard works as the live teaching surface.

Updated net zero transition roadmap

Partial

Two different roadmaps share a name. docs/bidv_implementation_roadmap.md is a 24-week adoption pathway for the tooling. The MoU means a net zero roadmap — sector interim reduction targets off a finalized baseline. PACTA SDA and market-share targets give the pathway curves; the target-setting layer on top is not written.

Updated Scope 3 financed emissions calculation toolset with input-data guidelines

Not in repo

No PCAF calculator, no emission-factor handling, no attribution-factor logic. The repo starts one layer downstream. See below.

KPI/SPT advisory inputs for two priority clients

Advisory work

The engagement letters carry per-sector actions including a covenant trigger, which is adjacent, but KPI and SPT design is judgement work rather than pipeline output. Treat as consulting delivery the repo supports with evidence, not automates.

Scope 1 & 2 assessment report; two hand-off trainings; rooftop solar / BESS / REC feasibility

Out of scope

Operational emissions and clean-energy feasibility sit entirely outside this codebase. Worth stating plainly in any internal resourcing plan so they don't get assumed into the platform's column.

Techcombank concept note: the repo is the deliverable

Output 1.2 describes this repository almost line for line

The note commits Allotrope to assess "leading portfolio alignment frameworks (potentially including SBTi for Financial Institutions or PACTA for Banks) as well as the TRISK against TCB's portfolio composition and data availability", evaluating "use cases, data requirements, and limitations" to found future IFRS S2 work.

docs/bidv_framework_comparison.md already scores a 7 × 10 matrix across PACTA, TRISK, PCAF, SBTi FI, GFANZ/NZBA, NGFS and IFRS S2 — the exact named set — on dimensions including data inputs, Vietnam regulatory compatibility, implementation complexity and time to first results. It carries a four-layer complementarity model (PCAF → PACTA → TRISK → IFRS S2) and a section on where peer frameworks outperform the recommendation.

Nothing in it is BIDV-specific at the methodology level. Retargeting to TCB is a client-context swap in scripts/generate_bidv_report.R plus a TCB engagement config — and unlike a desk study, it ships with a working PACTA + TRISK run and a public dashboard that demonstrate the data requirements and limitations empirically rather than asserting them.

The one structural gap

Both documents open at PCAF financed-emissions accounting. This repo opens one layer later, at PACTA alignment. That is not an oversight — the repo's own framework comparison classes PCAF as a prerequisite that is "already in place", assuming the inventory arrives from elsewhere.

That assumption held while BIDV's financed-emissions work was being done by hand (the January 2026 preliminary assessment: cement 5.84 MtCO₂e, iron & steel 3.23 MtCO₂e, coal thermal power 0.87 MtCO₂e). Both new documents scale that work up — BIDV to a repeatable toolset with input-data guidelines and a handover to their PCAF focal point; TCB to a full inventory across three asset classes.

So the question to settle before either scope is signed: does the PCAF layer become part of this platform, or stay a spreadsheet deliverable that feeds it? The repo's intake contract, FX-at-intake conversion and sector mapping are the natural foundation if the answer is the former — but it is a genuine build, not a refresh.

Drafting issues worth fixing before either document goes out

  • The BIDV MoU's English section carries unresolved redline residue. The Vietnamese section reads clean, but the English "for reference" version contains broken fragments — "Support BIDV to complete an", "T this cooperation continues into the 2026-2027 program period.", a stray "A" line, and two overlapping outcome lists where the old 2023 outcomes sit underneath the new ones. The document has a signature block dated 2026; the English half is not currently signable.
  • The TCB note says "four reinforcing tracks" and then lists three. The opening paragraph also contains both the old two-track sentence and the new three-objective sentence, one after the other.
  • The TCB note has two "Output 3.2" headings, the second one empty, and a few typos from the merge — "technicalassessment", a doubled period before "By evaluating".
  • Objective 1's opening sentence in the TCB note reads as two alternative drafts spliced together — the Scope 3 methodology version and the comprehensive baseline version — with no separator.

These are all merge artifacts from editing v1 into v2, not substantive problems. But the BIDV one matters most because that document is closest to signature.

What I'd do next

  1. Clean the English half of the BIDV MoU. Highest urgency, lowest effort, and it was edited this morning — so it is live.
  2. Decide the PCAF question. Build it into the platform or keep it external. Everything else in both scopes sits downstream of that answer, and it is the only decision here that changes the shape of the work.
  3. Spin a TCB engagement config and retarget the framework report. This turns TCB Output 1.2 from a promise into something demonstrable in the next conversation, and the orchestrator already supports a third engagement without a fork.
  4. Reframe engagement scoring onto SLL readiness for the BIDV shortlist-of-three commitment — new inputs and template, existing machinery.
  5. Fix the TCB note's merge artifacts before it goes to the client as "for review".
