What this wave was for

Waves 0–3 built three layers of verification — byte-identical CSVs, cross-artifact invariants, and a unit-test suite — and pointed all three at the numbers. Meanwhile the surface a client actually receives grew to 71 tracked HTML artifacts. None of it was gated: classify_path() returned "timestamp-class" for every .html file unconditionally, and no test asserted the content of any generated report.

Three provenance defects were sitting in that blind spot. This wave closes the blind spot, fixes the defects, and finishes the scale measurement Wave 3 started but could not complete.

The three provenance defects

1. The refresh audit attested to the wrong scenario vintage

scripts/generate_refresh_audit.R hardcoded every path it touched, including a 2023 scenario-vintage directory. Wave 3 moved mcb-demo to pdp8-2025-adjusted, so the audit went on publishing the MD5 digests of files the pipeline had not read.

FieldBefore (wrong)After (correct)
scenario_ms_checksum 1827b277… = pdp8-2023 7454bb5c27224d77df3da3fb97210e1d = pdp8-2025-adjusted
scenario_co2_checksum ce806a7c… = pdp8-2023 f3ff478f028dd53cbd6f2b18cd356890 = pdp8-2025-adjusted
scenario_vintagenot recorded pdp8-2025-adjusted

The script now takes --config and derives every path from the engagement config, and INV-012 checks that the recorded digests match the configured inputs. It fired on the committed defect before the fix.

2. The manifest and the audit contradicted each other

The committed pipeline_manifest.json reported "seconds": 1 for all 16 steps and status: ok, while the audit rendered from it showed engagement_scoring failed. The mechanism: a --only-step run overwrote the full-run manifest with only its own steps and marked it in no way. Manifests now carry partial, the orchestrator refuses to clobber a complete public manifest without --allow-partial-manifest, and INV-011 rejects a complete manifest whose steps all report one identical duration. The manifest now reports 11 distinct durations across 16 steps.

3. An analytic hardcoded the demo bank's slug

R/financed_emissions.R wrote data_source = "mcb-demo" on every row of every engagement's inventory. INV-003 existed to catch exactly this but only ever opened engagement_priority.csv; it now checks the three per-engagement CSVs Wave 3 added as well.

Correction to the planning documents. The brainstorm and plan described this as a committed fixture carrying the wrong slug. That was wrong: engagements/sdb-rehearsal/output/financed_emissions/financed_emissions.csv is gitignored (.gitignore:73) and has never been committed, so no incorrect value was ever in git. The hardcoded literal was real and is fixed; the accurate severity is "would mislabel any real engagement's inventory the moment it is generated". The planned fixture refreeze was unnecessary.

A fourth defect, found by the new gate

Not in the plan — surfaced by running the pipeline under the new checks. synthesis_output/prioritization/sector_priority_{ranking,detail}.csv carried a stress_score_raw for power of 4.355628082916891 that the repository could no longer reproduce. In a pristine git worktree at the pre-Wave-4 commit 503743f, with entirely unmodified code and data, scripts/sector_prioritization.R produces 4.343708488002581. Zero TRISK outputs changed, confirming the staleness was in the prioritization artifact rather than upstream. The committed artifact had never matched the inputs it claims to derive from.

composite_score (0.9224749999999999) and priority_band (Critical) are unchanged, because power's stress_score is capped at 1 — the moved value is a raw diagnostic column only, and the golden tests stay green.

The match_seconds gap was a broken harness, not slow matching

Every cell of the original benchmark read NA. The harness built a five-column loanbook subset and an ABCD with no sector column, so match_name() always raised Must have missing names: sector_classification_direct_loantaker and a tryCatch swallowed it. Fixed by passing the normalized loanbook whole (it is already the 13-column r2dii shape) and mirroring R/pacta_core.R's exact call, VSIC→ISIC extension included.

The result confirms the hypothesis Wave 3 could not test: intake scales with loan count and is flat in counterparty count; matching is the opposite — at a fixed 50,000 loans, going from 200 to 5,000 distinct counterparties takes matching from 6.8 s to 26.9 s.

What was not done, and why

  • TASK-05-08, the --full-chain benchmark. It cannot be done honestly with the current fixture: tools/generate_scale_fixture.R emits a loanbook and an ABCD table only, while the stages past PACTA matching need asset-level inputs (assets, financial features, carbon prices, scenarios) for the synthetic counterparties. Fabricating them would time a fiction. Recorded as still-unmeasured in docs/scale_benchmark.md; extending the fixture generator is the prerequisite and belongs to a later wave.
  • TASK-04-02 turned out unnecessary. pacta_market_share already carried #' @export (R/pacta_core.R:362); the planning-time scan missed it because @param lines sit between the tag and the definition. Roxygen added 22 exports and removed none, confirming there was no discrepancy to fix.
  • Two suspected bugs were tested and are not bugs. attribution_factor() with an NA capital and sda_convergence_target() with a zero-length baseline both return NA cleanly. Left unchanged; the new tests lock that behaviour in.

Calibrating the gate

The gate found two false positives in its own first full run, both run-scoped noise rather than content: the audit report renders wall-clock step durations, and the PACTA report embeds charts as base64 PNGs whose compression is nondeterministic — the very noise the standalone-.png rule already excludes. Both are now normalized away.

One ordering bug of my own making was found and fixed: a base64 payload contains long runs of [0-9a-f], so applying the git-SHA rule before the image rule punched <SHA> tokens into the middle of payloads and broke the image pattern's contiguous match. The image rule now runs first, covered by a regression test. Tampering with a table cell in each gated report still classifies as drift, so the gate remains calibrated rather than merely quiet.
