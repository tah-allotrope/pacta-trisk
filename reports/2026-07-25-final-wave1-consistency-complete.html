02 / Background & Objective

Background & Objective

PACTA + TRISK Vietnam demonstrates how a fictional Vietnamese bank could measure loanbook climate alignment (PACTA) and transition-risk stress (TRISK) from a fully synthetic dataset. Wave 0 (five commits, completed before this wave) built a config-driven engagement runway — scripts/run_engagement.R could run the full delivery flow for any bank — and tools/verify_refactor.R made "does this refactor leave every CSV byte-identical?" a one-command check.

A same-day research pass found that Wave 0's acceptance discipline had a precise blind spot: it verifies that run N+1 matches run N (reproducibility), but never that artifact A agrees with artifact B (consistency). The most visible symptom: the precomputed TRISK scenario grid powering the dashboard's Scenario Builder had gone stale three months earlier and, at default parameters, disagreed with the TRISK Risk page for the same borrower. Five sibling defects — a hardcoded provenance literal, a sector-prioritization function that ignored its own config, duplicate scenario files, an ABCD schema violation, and a CI guard that a prior report claimed existed but didn't — lived in the same blind spot.

Wave 1's objective was to close that blind spot structurally rather than patch each symptom independently: build the detector first, then let it drive every subsequent fix, converge the platform's two divergent orchestrators, and leave the CI pipeline actually guarding what it claims to guard.

04 / Assumptions & Constraints

Assumptions & Constraints

Binding Decisions That Held

  • Detector before fixes (DEC-001): Phase 1 was accepted only once it proved it could fail — exit 1 naming INV-001/002/003 on the untouched tree. Every later phase's exit criterion was "does this specific invariant now pass," not a vaguer "does it seem better."
  • No new pipeline dependency (CON-001): held throughout, including the grid fingerprint (built from base R tools::md5sum() rather than pulling in the digest package for a single string hash).
  • Convergence direction (DEC-003): pipeline_refresh.R → run_engagement.R, never the reverse. Held; the wrapper is nine lines forwarding whatever flags it receives.

Assumptions Revised Mid-Wave (With Evidence)

  • The "inert" levers weren't both inert. The plan's own Specification S3 anticipated risk_free_rate might be a plumbing bug; measurement showed it is fully live — it moves probability of default by up to 2.8 points, just never NPV. The original brainstorm's "inert" finding had only checked NPV. No plumbing bug existed; the lever was kept unchanged.
  • Fixing the grid's cache wasn't sufficient. Phase 4's plan assumed input-fingerprinting alone would make the grid's base cell match the base run. A first full regeneration proved otherwise — a second, architectural cause (a shared input package silently extending every scenario's data horizon) had to be found and fixed before the invariant actually passed.
05 / Methodology

Methodology

Each phase was gated on a shell-verifiable exit criterion before the next began, mirroring the discipline that worked in Wave 0: build the check, prove the check can fail, fix until it passes, move on. Every phase's changes were verified at three levels — unit tests against isolated fixtures (never the live tree, so they stay green through later phases regardless of what the data says at that moment), a live subprocess run of the actual orchestrator, and a byte-for-byte diff of every changed artifact to confirm a fix touched only what it intended to.

Two points where the plan's own text turned out to be incomplete were resolved by measurement rather than by following the plan literally: the risk-free-rate lever's true behavior (Assumptions, above), and the grid's second root cause (Phase 4, below). In both cases the response was the same — stop, measure directly against the running system, and let the evidence override the prior plan rather than patch around a symptom.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — the detector class of defect was real and multiplicative. Five of five invariants were meaningful (none was a false-positive tripwire), and fixing them surfaced two additional defects the original plan never anticipated: the grid's horizon-extension bug (Phase 4) and a second jsonlite round-trip hazard (Phase 6). Both were found only because a phase's exit criterion was "does the check pass," which forced continued investigation when a first fix proved insufficient — a plan that had stopped at "input fingerprinting done" would have shipped a grid that still silently disagreed with the base run.

Finding 2 — fixture-content tests are a specific, nameable failure mode, not just a vague gap. test_sdb_engagement.R passed for months while guarding artifacts nobody had regenerated since PHASE-02. The row_count_files bug in Phase 6 (a second instance of the exact class of bug Phase 2 already found once) existed in committed code for one full phase before being caught — because the only test exercising that code path required an environment variable nobody sets by default. This is now lessons.md's entry #4, generalized rather than left as a one-off note.

Finding 3 — "the lever is inert" needs a metric, not an inspection. risk_free_rate was declared inert in the original brainstorm on the strength of one comparison (NPV sums). It was live all along — just for PD, a different metric nobody had checked. The corrected finding is documented with its evidence in docs/TRISK_Demo_Assumptions.md, not just fixed silently.

Recommendation: the platform's acceptance discipline is now symmetric — it can prove both "this run reproduces itself" and "these artifacts agree with each other." The natural next investment is extending the same detector-first discipline to methodology credibility (the brainstorm's M-series findings: rank-relative composite scores that are always exactly 1.0 by construction, implausible loanbook magnitudes) — deferred out of this wave's scope by design, and now unblocked by a codebase with zero known cross-artifact inconsistencies to confound the next investigation.

08 / Implementation Path

Implementation Path

Immediate: nothing blocking

Wave 1 is complete and self-verifying. tools/verify_refactor.R --invariants runs in CI on every push and every weekly refresh — a future regression in any of the five checked properties will fail loudly in CI rather than silently accumulate for months, which is exactly what happened to the grid this wave.

Carried forward, not started

The brainstorm's credibility-analytics backlog (multi-scenario traffic-light matrix, absolute/anchored composite scoring, executive summary generator) remains explicitly out of scope for this wave and unattempted. It is the natural Wave 2 candidate, now on a foundation with no known data inconsistencies.

Worth a deliberate look

Two defects (Phase 4's horizon bug, Phase 6's second jsonlite hazard) were found only through direct execution, not through static review of the plan. A brief audit for other places the same jsonlite empty-vector pattern could recur (any optional config key defaulting to an empty vector) would be cheap insurance before the next engagement config gains new optional keys.

Process note

lessons.md now exists at the repo root, seeded with five entries. The project's own workflow expects it reviewed at the start of every session and updated after corrections — this wave is the first to actually create it, closing a hygiene gap three prior brainstorms had flagged and left open.

09 / Risks / Open Questions

Risks / Open Questions

Resolved This Wave

  • The plan's own RISK-002 (invariants added to refresh.yml before Phase 4 landed would have blocked every Monday's publish since May) was avoided by sequencing: the invariants step was added to refresh.yml only in Phase 6, after Phase 4 had already made every invariant pass.
  • RISK-003 (grid regeneration could reveal a carbon_price_model name trisk.model rejects) was pre-empted by a single-scenario probe before the full 3-sector, ~15-minute regeneration — caught the horizon-truncation crash on the very first scenario of a full run instead of after it.

Open, Carried Forward

  • The grid regeneration is now correct but remains the wave's longest single operation (~450s for power alone). If a future engagement needs its own grid, this cost recurs per engagement — worth revisiting if a third or fourth bank's grid is requested before a caching strategy (e.g. targets) is evaluated, as the original Wave-0 backlog already anticipated.
  • The jsonlite empty-vector round-trip hazard (lessons.md #5) is a pattern, not a single fixed instance — any future optional config key defaulting to an empty vector is at risk until a config-level round-trip test exists generically rather than per-field.
