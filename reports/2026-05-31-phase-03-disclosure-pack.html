03 / Math / Algorithm Used

Math / Algorithm Used

Assembly logic rather than statistics:

  • Self-contained md→HTML: a small converter handles headers, lists, blockquotes, rules, and inline bold/code/links; an HTML-comment stripper drops the template's editor notes so they never reach the page.
  • Section extraction: extract_section(md, header, next_header) pulls bounded appendix excerpts (PACTA "What is PACTA", TRISK "Purpose" + "Interpretation Guardrails", Decision 263 "Overview") so the appendix stays condensed and the file stays small.
  • Anonymisation (RISK-03-01): one borrower-name list, applied longest-name-first with fixed-string replacement across the fully-assembled HTML, so a short name (e.g. "EVN") can never partially match inside a longer one. A grep over the output confirms zero real names remain.
  • Graceful degradation: any missing input becomes a "[section pending]" callout instead of crashing the run (pre-flight pattern from generate_bidv_report.R).

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Demo regulatory wording: TCFD/ISSB/Decision 263 narrative is illustrative; a domain reviewer must confirm the regulatory phrasing before any filing (the disclaimer says so).
  • English-with-Vietnamese-terms (Q-002): the pack is English-primary with Vietnamese key terms, not a full bilingual document — matching the BIDV report convention.
  • Anonymisation is name-list based: it removes the known borrower names robustly (verified by grep), but a free-text addition that named a borrower in a new way would need the name added to the priority table to be caught. Mitigated by sourcing every name from the same priority CSV.
  • Second-best alternative (rejected): a native PDF/DOCX renderer (ALT-001). Deferred for v1; print-to-PDF from self-contained HTML matches the repo pattern and adds no dependency.
